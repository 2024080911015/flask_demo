# 画像问卷功能修改说明

## 1. 修改背景

本次修改围绕“注册时可填写调查问卷，并将问卷结果用于完善用户画像和好友推荐”展开。原系统主要依赖用户基础资料、兴趣标签、社交关系和 GNN embedding 做推荐；新增问卷后，系统可以在冷启动或用户资料较少时获得更细粒度的匹配因子。

问卷采用独立页面承载，而不是直接堆叠在注册弹窗中。这样可以减少注册页的信息压力，同时让用户在登录后也能重新填写问卷，持续更新自己的画像。

## 2. 功能目标

- 注册界面提供“填写画像问卷”的可选入口。
- 问卷作为独立页面展示，路径为 `/questionnaire`。
- 问卷题目采用选择式交互，减少用户输入负担。
- 后续题目会根据用户前序答案动态出现，形成简化的决策树问卷。
- 用户可以跳过问卷完成注册。
- 已登录用户可以在“个人空间”中重做问卷。
- 后端根据问卷答案量化用户画像维度，并写入用户 `info` 字段，供推荐逻辑使用。

## 3. 前端交互说明

### 3.1 注册阶段

注册页新增“填写画像问卷（可选）”按钮。用户可以先进入问卷页面填写，也可以直接点击“下一步：完善资料”完成基础资料选择。

问卷填写完成后，答案会暂存在前端 `QuestionnaireState.answers` 中。用户返回注册流程并提交注册时，前端会把问卷答案一起提交给 `/api/register`。

如果用户没有填写问卷，注册仍然可以正常完成。后端不会强制生成画像分字段。

### 3.2 独立问卷页面

新增页面模板：

```text
templates/questionnaire.html
```

页面特征：

- 单题逐步填写。
- 顶部显示问卷进度。
- 每题以卡片按钮形式选择答案。
- 支持 1-5 档量表题。
- 支持“稍后再填”和“返回”。
- 支持选填补充描述，最多 80 字。

页面由 SPA 路由控制，新增路径：

```text
/questionnaire
```

### 3.3 动态分支逻辑

问卷题目中包含 `followupFor` 配置，用于控制后续问题是否出现。

示例：

```js
{
  id: 'introvert_contact',
  title: '如果你更慢热，哪种破冰方式压力最低？',
  followupFor: { id: 'social_scene', values: ['one_on_one'] }
}
```

当用户在 `social_scene` 中选择“一对一慢慢熟悉”时，系统会展示慢热破冰方式问题；如果用户选择“小范围共同活动”或“社团/比赛/活动现场”，则展示活动偏好问题。

### 3.4 登录后重做问卷

个人空间新增“重做画像问卷”按钮。已登录用户点击后进入同一个 `/questionnaire` 页面。

重做完成后，前端调用：

```text
POST /api/questionnaire/update
```

后端会更新画像相关字段，但保留用户原有基础资料、爱好和手动选择的标签。

## 4. 问卷维度设计

当前问卷将用户答案转化为 6 个画像维度：

| 维度 | 含义 |
|---|---|
| social | 社交主动性和社交能量 |
| collaboration | 组队协作倾向 |
| learning | 学习、竞赛、科研驱动力 |
| openness | 对陌生圈子和新活动的开放程度 |
| communication | 沟通表达和分歧处理方式 |
| schedule | 作息规律与时间匹配倾向 |

后端会将各题分值按维度聚合，并计算平均分，形成类似如下的画像字段：

```text
画像分:社交83|协作73|学习74|开放75|沟通80|作息35
社交倾向:公开活动型 组织推进 竞赛科研 夜间活跃 直接沟通
自述:想找项目搭子
```

这些字段会拼接进 `UserInfo.info`，因此现有推荐、搜索、用户卡片、社交诊断和后续 GNN 重训流程都可以继续读取同一个资料字段。

## 5. 推荐算法融合方式

本次继续修改后，画像分已经不只是写入用户资料，而是会被 `step3_recommend.py` 中的推荐排序直接使用。

推荐流程如下：

1. 先使用 GNN embedding 计算目标用户与所有候选用户的基础相似度。
2. 从候选用户 `info` 中解析 `画像分:` 字段，得到 6 维画像向量：

```text
[社交, 协作, 学习, 开放, 沟通, 作息]
```

3. 对目标用户与候选用户的画像向量计算余弦相似度，并归一化为 0-100 分。
4. 在 `social` 模式下，再计算共同关注关系带来的社交加成。
5. 最终按综合分排序，返回 Top-K 推荐用户。

当前排序权重如下：

### gnn 模式

`gnn` 模式保留“相似度优先”的语义，但加入少量画像修正：

```text
final_score = 0.80 * gnn_score + 0.20 * profile_score
```

含义：

- `gnn_score`：GNN embedding 余弦相似度，归一化为 0-100。
- `profile_score`：问卷画像 6 维向量的余弦相似度，归一化为 0-100。

### social 模式

`social` 模式同时考虑 GNN 相似度、画像相似度和社交网络加成：

```text
final_score = 0.60 * gnn_score + 0.25 * profile_score + 0.15 * social_bonus
```

含义：

- `gnn_score`：模型学习到的总体相似度。
- `profile_score`：问卷画像维度相似度。
- `social_bonus`：共同关注数量带来的社交图加成。

如果某个用户没有填写问卷，`profile_score` 会使用中性分 50，避免老用户或未填写问卷用户被异常惩罚。

相关代码入口：

```text
step3_recommend.py
```

新增核心函数：

- `parse_profile_scores(info_str)`：解析 `画像分:` 字段。
- `get_profile_similarity(user_id, target_id)`：计算画像相似度。
- `get_social_bonus(user_id, target_id)`：计算共同关注加成。
- `recommend_friends(...)`：将画像相似度纳入最终排序。

## 6. 后端接口说明

### 6.1 注册接口扩展

接口：

```text
POST /api/register
```

新增可选字段：

```json
{
  "questionnaire": {
    "social_scene": "small_group",
    "team_role": "specialist",
    "study_drive": "competition",
    "schedule": "stable",
    "conflict_style": "balance",
    "activity_radius": 4,
    "event_preference": "workshop",
    "self_description": "想找项目搭子"
  }
}
```

注册成功后，如果提交了有效问卷，返回值中会包含：

```json
{
  "profile_scores": {
    "social": 69,
    "collaboration": 74,
    "learning": 85,
    "openness": 68,
    "communication": 65,
    "schedule": 70
  }
}
```

### 6.2 重做问卷接口

新增接口：

```text
POST /api/questionnaire/update
```

要求用户已登录。请求体格式与注册接口中的 `questionnaire` 一致。

接口行为：

- 读取当前用户已有 `UserInfo.info`。
- 移除旧的 `画像分`、`社交倾向`、`自述`字段。
- 重新计算画像分和衍生标签。
- 合并回用户资料。
- 更新内存中的 `user_info_map`，保证接口立即返回新画像。

## 8. 数据兼容性

本次修改没有新增数据库表，也没有改变现有表结构。

画像结果仍写入 `users.info` 字段，保持与原推荐系统兼容。已有用户不受影响，只有在重做问卷后才会新增画像字段。

推荐算法对未填写问卷的用户使用中性画像相似度，因此旧数据可以继续参与推荐，不需要立即迁移。

## 10. 后续可优化方向

- 将画像分拆成独立数据库字段，避免长期依赖 `info` 字符串解析。
- 根据真实点击、关注、组队申请数据继续调优 `gnn_score`、`profile_score`、`social_bonus` 的权重。
- 在个人空间展示画像雷达图，让用户看到自己的社交画像。
- 增加问卷答案回显，方便用户重做时看到上一次选择。
- 为问卷题目和分值规则建立后台配置，减少后续改题时的代码改动。
